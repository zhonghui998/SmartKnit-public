# SmartKnit — AI 驱动的针织定制电商引擎

> 把任意一张照片或手绘稿，在 60 秒内变成「工厂能直接上机生产」的针织图案，并完成选品、换色、下单、生产交付的完整闭环。

---

## 一、解决什么问题

传统针织定制有四个断层，任何一环断了，生意就做不成：

| 断层 | 传统做法 | 我们的做法 |
|---|---|---|
| **照片 ≠ 图案** | 设计稿是照片，上机织出来糊成一团 | AI 按目标针织网格重绘，从生成阶段就按针数约束构图 |
| **图案 ≠ 工艺** | 图案好看但颜色数、线条粗细超出机器能力 | 生成前读取产品的针数/色数/工艺上限，按约束作画 |
| **客户看不懂** | 客户不知道 82 针能表达什么，反复退改 | 实时预览 + 逐色换色，所见即所得 |
| **订单 ≠ 生产** | 设计稿重新描图、工厂反复确认 | 直接输出工厂格式文件 + 自动生产工单 |

一句话：**把「设计语言」自动翻译成「机器语言」**。

## 二、产品能力

### 支持的产品线（30 个 SKU）

| 类别 | 代表产品 |
|---|---|
| 手提袋 / 托特 | 横款 / 竖款 / 斜背 / 迷你 |
| 电脑包 / 平板包 | 13"–16"、横竖两版 |
| 居家织物 | 杯垫、方巾、鼠标垫、挂毯 |
| 艺术打印 | A3 / A4 / A5 针织画 |
| 配件 | 钥匙扣、织带、行李牌、登机牌 |

### 核心能力

- **照片 → 针织图**：AI 重绘，自动适配目标针数（82×64 到 270×156）
- **手绘稿 → 针织图**：内容识别分流，文字走字体排版、图形走 AI 重绘
- **智能换色**：识别图案色块，逐块替换成真实纱线色，其他区域像素级不动
- **一键还原**：逐像素回到 AI 原始设计
- **实时预览**：合成到真实产品图上，含袋身底色联动
- **生产就绪**：直接输出针数级设计文件 + 自动生成生产邮件

## 三、技术架构

```
┌─────────────────────────────────────────────────────────────┐
│  前端定制器（浏览器内运行，无需安装）                          │
│  · 上传 / 拍照    · 实时预览    · 点图选区    · 换色面板       │
└──────────────────────────┬──────────────────────────────────┘
                           │ HTTP / JSON
┌──────────────────────────▼──────────────────────────────────┐
│  业务层 API                                                   │
│  · 产品模板驱动（30 个 SKU 的差异全部数据化）                  │
│  · 规格解析：针数 / 色数 / 色板 / 内容预算                     │
│  · 订单与 Shopify 集成    · 生产交付流水线                     │
└──────────────────────────┬──────────────────────────────────┘
                           │
        ┌──────────────────┼──────────────────┐
        ▼                  ▼                  ▼
┌───────────────┐  ┌───────────────┐  ┌───────────────┐
│ 内容识别       │  │ AI 生图        │  │ 针织化引擎     │
│ 视觉理解分流    │  │ 提示词工程      │  │ 网格量化 / 合成 │
│ 文字/图形判断   │  │ 画布比例约束    │  │ 区域识别 / 渲染 │
└───────────────┘  └───────────────┘  └───────────────┘
```

### 分层原则

- **产品模板数据化**：30 个 SKU 的针数、色数、工艺参数、合成位置全部由 JSON 驱动，新增产品不改代码
- **规格解析单一来源**：一处决定「这个产品能表达什么」，AI 生成、换色面板、生产输出共用同一份规格
- **生图与针织解耦**：AI 只负责「画得对」，针织引擎只负责「织得出」，各自独立演进

## 四、系统组成

系统由四类能力模块构成，按职责边界划分：

| 能力 | 职责 |
|---|---|
| 产品与配置 | 30 个 SKU 的尺寸、纱线色板、工艺参数、成品合成位置，全部以配置驱动 |
| 内容生成 | 照片与手绘稿的内容理解、图案重绘、画布适配 |
| 针织处理 | 网格量化、密度换算、区域识别、产品合成 |
| 交易与交付 | 定制下单、订单同步、生产工单生成与投递 |

前端为单页定制器，无构建依赖，浏览器直接运行。

模块之间通过明确的接口边界协作：配置层只描述「这个产品是什么」，处理层只回答「这张图能不能织」，交易层只关心「客户确认了什么」。三者互不侵入，新增产品线不需要改动处理逻辑。

## 五、我们面对的四个行业难题

### 1. 内容的丰富度 vs 工艺的表达力

一张手机照片有数十万种颜色，而一枚针织杯垫只有五千余个针位。

这个数量级差距不是「压缩」能解决的。系统的应对原则是：**先确定产品能表达什么，再让内容按这个边界生成**，而不是先生成再裁剪。

### 2. 生成式模型的输出不稳定

同一组输入条件，模型两次产出的复杂度可能相差几个数量级。

定制场景不能接受「这次好下次坏」。系统的应对原则是：**把不稳定性挡在交付之前**——无论模型给出什么，最终交付的图案质量都收敛到同一标准。

### 3. 局部修改不能影响全局

客户只改了图案里的一块颜色，其余部分必须保持原样。早期方案在这点上不合格，客户会认为「你把我的图改坏了」。

系统的应对原则是：**编辑的最小作用域必须可控**，改哪里就只影响哪里。

### 4. 素材比例与成品比例不匹配

客户上传竖版照片，成品是横向的包袋。直接裁切会丢掉大半内容。

系统的应对原则是：**在生成阶段就解决构图问题**，而不是事后拉伸或裁剪。
